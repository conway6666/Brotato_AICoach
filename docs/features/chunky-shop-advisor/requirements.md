## 1. 输出文件

`docs/features/chunky-shop-advisor/requirements.md`

## 2. 需求目标

| 项目 | 内容 |
| --- | --- |
| feature-slug | `chunky-shop-advisor` |
| 目标类型 | feature |

## 3. 背景与目标

`chunky-shop-advisor` 面向《土豆兄弟》大块头（Chunky）玩家，在商店购买和升级属性选择前提供克制、可信、可解释的建议。目标是帮助玩家理解当前候选项的相对价值，避免明显低收益选择，同时保留玩家自主决策。

该功能默认自动触发，但不能阻塞操作、不能遮挡商店或升级选择内容，也不能替玩家购买、加点或刷新。

## 4. 目标用户

| 玩家类型 | 使用场景 |
| --- | --- |
| 新手玩家 | 不清楚 Chunky 的生命值收益和 `%伤害` 规则，需要避免明显错误选择。 |
| 进阶构筑玩家 | 想快速比较商店商品、升级属性和当前构筑方向的匹配度。 |
| 高难挑战玩家 | 需要根据当前 Wave、属性、武器和金币判断是否补生存、补输出或保守刷新。 |

## 5. 用户故事

```text
作为一名正在使用 Chunky 的 Brotato 玩家，
当我进入商店或升级属性选择界面时，
我希望 AI 伴侣能够基于当前角色数值、武器、道具、金币和候选项给出排序、简短理由和是否刷新建议，
以便我在不被界面打断的情况下做出更稳妥的构筑选择。
```

## 6. 防剧透与引导尺度

| 项目 | 定义 |
| --- | --- |
| 默认剧透等级 | L2：方向性策略，不强行输出唯一最优解。 |
| 禁止输出内容 | 不输出完整攻略路线；不声称玩家必须购买、必须加点或必须刷新；不替玩家操作。 |
| 允许输出内容 | 当前可见商品/属性的优先级、简短理由、风险标签、保守刷新建议和方向性构筑提醒。 |
| 是否允许用户手动提升尺度 | 是，后续可通过追问或设置进入 L3 高级构筑分析。 |
| 高风险剧透场景 | 将社区流派定式或高难最优解包装成唯一答案；忽视玩家实际选择而强行套模板。 |

## 7. 功能范围

### Must Have

- 在进入商店界面时默认自动生成轻量建议。
- 在进入升级属性选择界面时默认自动生成轻量建议。
- 建议 UI 必须非阻塞，不遮挡商店商品、升级选项、金币和关键角色信息。
- 对当前可见商品输出优先级排序、简短理由和购买/跳过倾向。
- 对当前可见升级属性输出优先级排序、简短理由和选择倾向。
- 给出保守刷新建议：只有当前候选整体价值明显偏低，且金币足够保留关键购买空间时，才建议刷新。
- 每次建议都必须基于最新角色数值、武器、道具、金币、Wave 和当前候选项重新判断。
- 如果玩家没有遵循上一轮建议，后续建议必须尊重既成选择并动态修正方向。
- 默认建议控制在 3 行以内，必要时可提供展开或追问入口。

### Should Have

- 标注每个高优先级选择的主要收益来源，例如生命值双重收益、EHP 提升、DPS 提升、经济收益或风险缓解。
- 对 Chunky 低收益或无收益项给出明确避坑提示，例如常规 `%伤害` 对 Chunky 的低价值。
- 在输出中区分“强推荐”“可选”“跳过”“考虑刷新”等轻量标签。
- 支持玩家手动关闭自动提示或改为按钮触发。

### Could Have

- 提供 L3 高级分析入口，展示更完整的商品评分、属性权重或转型解释。
- 记录玩家连续选择偏好，用于后续建议语气和排序解释。
- 对锁定商品、下一波风险和预计剩余金币给出更细预算提示。

### Won't Have

- 不做自动购买、自动加点、自动刷新或托管玩法。
- 不做战斗中实时提示。
- 不做多角色完整覆盖。
- 不做完整 Wiki/RAG 问答。
- 不承诺输出全局最优构筑路线。

## 8. 输入数据

| 类型 | 数据 |
| --- | --- |
| 局内状态 | 当前 Wave、金币、商店刷新成本、是否处于商店或升级选择界面。 |
| 角色状态 | Chunky 当前生命值、护甲、闪避、伤害相关属性、攻速、范围、暴击、生命窃取、再生、收获等。 |
| 装备与道具 | 当前武器列表、已有关键道具、道具带来的属性变化和标签。 |
| 候选项 | 当前商店商品、价格、锁定状态、属性变化；当前升级属性选项及数值。 |
| 规则知识 | Chunky 生命值增幅、生命值转伤害、常规 `%伤害` 低收益规则、波次风险和基础构筑规则。 |
| 玩家配置 | 自动触发开关、提示深度、是否允许 L3 高级分析。 |

## 9. 输出形式

- 默认使用游戏内轻量浮窗或气泡。
- 内容不超过 3 行，包含：
  - 商品或加点优先级摘要。
  - 1-2 条简短理由。
  - 是否建议刷新。
- 输出不应遮挡玩家查看商店商品、升级选项、价格、金币和角色关键信息。
- 可提供“展开解释”或“追问”入口，但默认不展开长篇攻略。

示例：

```text
优先：+HP 道具 > 护甲；跳过纯 %伤害。
+HP 同时提升坦度和 Chunky 隐性伤害，护甲补下一波容错。
不建议刷新：当前已有可买核心项，先保留金币。
```

## 10. 触发规则

| 触发条件 | 默认行为 |
| --- | --- |
| 进入商店界面 | 自动生成非阻塞建议。 |
| 商店商品变化或刷新后 | 基于最新商品、金币和角色状态重新生成建议。 |
| 进入升级属性选择界面 | 自动生成非阻塞加点建议。 |
| 玩家购买、跳过、加点或改变装备后 | 下一次建议基于最新状态动态修正，不沿用旧假设。 |
| 玩家关闭自动提示 | 不自动弹出，仅保留按钮触发。 |

## 11. 异常与降级策略

| 场景 | 降级行为 |
| --- | --- |
| 缺少商店或升级候选数据 | 明确提示“当前候选项读取不完整”，不输出排序结论。 |
| 缺少部分角色属性 | 仅基于可用数据输出低置信建议，并标注缺失项。 |
| 规则无法覆盖某件物品 | 不编造数值收益，标注为“需要人工确认/低置信”。 |
| LLM 超时或不可用 | 输出确定性规则生成的简短建议或提示稍后重试。 |
| 当前商店价值判断不明确 | 不建议刷新，提示“当前没有明显刷新理由”。 |

## 12. 验收标准

| 编号 | 场景 | 输入 | 预期输出 |
| --- | --- | --- | --- |
| AC-1 | 商店自动触发 | 玩家使用 Chunky 进入商店，存在 4 个商品、金币和角色属性数据完整 | 自动显示不超过 3 行的非阻塞建议，包含商品优先级、简短理由和是否刷新。 |
| AC-2 | 升级属性自动触发 | 玩家进入升级属性选择界面，存在 4 个属性候选 | 自动显示加点优先级和简短理由，不遮挡属性选项。 |
| AC-3 | 保守刷新 | 当前商品整体低价值，金币足以支付刷新且仍保留关键购买空间 | 输出“可以/建议考虑刷新”及一句理由。 |
| AC-4 | 不滥用刷新 | 当前商店存在至少一个高价值候选或金币不足 | 输出“不建议刷新”或“不急着刷新”，不得鼓励追逐未知最优解。 |
| AC-5 | 动态修正 | 玩家上一轮未采纳建议，购买了其他道具或选择了其他属性 | 下一轮建议基于最新角色数值、装备和候选项重新排序，不要求玩家回到旧路线。 |
| AC-6 | Chunky 规则命中 | 候选项包含纯 `%伤害` 与生命值相关收益 | 建议中应降低纯 `%伤害` 优先级，并说明 Chunky 更偏好生命值相关收益。 |
| AC-7 | 数据缺失 | 商店候选或关键属性读取不完整 | 不输出确定排序，明确提示数据不完整并给出降级建议。 |

## 13. 需要交给 game-architect 的信息

- 需要定义商店界面、升级属性界面和候选项变化的触发事件。
- 需要设计非阻塞 UI 契约，确保建议不遮挡商店商品、升级选项、金币和关键属性。
- 需要定义计算输入输出结构：角色属性、武器、道具、候选商品、升级候选、金币、刷新成本、Wave。
- 需要区分确定性计算结论与 LLM 文案生成职责，避免 LLM 自行心算。
- 需要支持状态变化后的重新计算，不能复用过期建议。
- 需要定义刷新建议的保守阈值、低置信输出和缺失数据错误状态。
