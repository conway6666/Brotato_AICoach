# Brotato AI Coach PRD

## 1. 产品愿景

打造一个坐在玩家身边、高情商、懂数值的《土豆兄弟》AI 军师。它在不替玩家操作、不打断心流的前提下，基于当前游戏状态给出可信、克制、可解释的构筑建议。

首期愿景聚焦大块头（Chunky）商店阶段：先证明 AI 能用确定性计算识别非线性收益和避坑项，再逐步扩展到更丰富的交互体验。

## 2. 目标玩家

| 玩家类型 | 需求 |
| --- | --- |
| 新手玩家 | 不理解角色机制和道具收益，希望减少明显错误选择。 |
| 进阶构筑玩家 | 想快速判断商店中多个选项的性价比和转型方向。 |
| 高难挑战玩家 | 需要根据当前数值和波次风险做更精确的 ROI 判断。 |
| 休闲陪伴型玩家 | 希望获得安心感和简短解释，而不是切出游戏查攻略。 |

## 3. MVP 范围

### In Scope

- 游戏：Brotato / 土豆兄弟。
- 角色：大块头（Chunky）。
- 场景：商店阶段。
- 目标：数值正确性优先，交互最小闭环。
- 核心能力：
  - 识别 Chunky 的生命值增幅与生命值转伤害机制。
  - 识别常规 `%伤害` 修饰词对 Chunky 无收益。
  - 计算购买道具前后的 EHP、DPS 和 ROI。
  - 基于当前属性、武器、波次和商店候选给出购买/跳过/转型建议。
  - 将计算结论压缩成 3 行以内的轻量建议。

### Out of Scope

- 多角色支持。
- 战斗中实时提示。
- 自动购买、自动加点或托管玩法。
- RPG 剧情防剧透系统。
- 完整 Wiki/RAG 问答。
- 多游戏通用适配框架。

## 4. 核心用户场景

玩家进入商店阶段后按下快捷键。系统读取当前 Wave、角色、基础属性、武器和商店候选物品，把数据交给确定性计算工具，得到 EHP、DPS、ROI 和风险标签。LLM 只负责把这些结论转译为简短、安心、可解释的建议。

示例输出目标：

```text
优先买 +HP 道具：它同时提升坦度和 Chunky 的隐性伤害。
跳过纯 %伤害：这个词条对 Chunky 基本没有收益。
下一波补护甲/收获，别硬转攻速。
```

## 5. 产品原则

- 数值先于话术：关键判断必须来自确定性计算或显式规则，不能让 LLM 自行心算。
- 克制提示：默认只给最关键建议，避免长篇攻略打断心流。
- 玩家保留控制权：系统只建议，不自动执行。
- 动态修正：如果玩家偏离标准攻略，基于既成事实给出转型建议，而不是强行套模板。
- 低剧透：Brotato 首期几乎无剧情剧透风险；未来 RPG 场景必须另设进度边界。

## 6. 成功指标

| 指标 | 首期目标 |
| --- | --- |
| 数值规则正确性 | Chunky `%伤害` 无效、生命值双重收益等核心规则稳定命中。 |
| 推荐可解释性 | 每条建议能追溯到 EHP、DPS、ROI 或明确机制规则。 |
| 建议简洁度 | 默认建议控制在 3 行以内。 |
| 交互打断感 | 商店阶段触发，不影响战斗操作。 |
| 可扩展性 | 计算输入输出结构可被后续多角色和 UI 复用。 |

## 7. 数据与知识需求

首期优先使用结构化、可测试的数据，不依赖完整 RAG。

- 角色数据：Chunky 的最大生命值增幅、生命值转伤害、无常规 `%伤害` 收益规则。
- 物品数据：商店候选物品的属性变化、价格、标签和限制。
- 武器数据：当前武器基础伤害、攻速、缩放属性。
- 局内状态：Wave、当前属性、已有武器、已有关键道具。
- 策略数据：波次-属性及格线、常见转型风险和避坑规则。

## 8. 风险

| 风险 | 影响 | 缓解方向 |
| --- | --- | --- |
| LLM 数值幻觉 | 推荐错误、失去信任 | 用确定性 Python 工具输出数值结论，LLM 不负责心算。 |
| Mod 数据不稳定 | 无法实时读取状态 | 先用 mock 数据验证算法，再接入真实数据。 |
| UI 过度打扰 | 破坏游戏心流 | 默认 3 行气泡，深度聊天作为可选追问。 |
| 规则维护成本 | 游戏更新后建议失真 | 结构化知识库与测试样例同步维护。 |
| 范围蔓延 | MVP 延期且验证失焦 | 首期只做 Chunky 商店阶段。 |
